# Boogerman (EU) — RAM map & vector findings (M2 RE pass)

Established from the ROM vectors and the first-pass generated C
(`native/generated/`, regenerated by the build). Addresses are 68000 bus
addresses; work RAM is `$FF0000-$FFFFFF`.

## Vectors (ROM header area)

| Vector | Address | Value |
|---|---|---|
| Initial SSP | $000000 | $00FF0200 |
| Reset PC | $000004 | $00000210 |
| IRQ4 (HBlank) | $000070 | $00006C14 |
| IRQ6 (VBlank) | $000078 | $00004DF0 |

Note: IRQ1-7 vectors live at $64-$7C (vector number × 4), not $44-$5C.

## VBlank handler ($004DF0)

1. `MOVEM.L D0-D7/A0-A6,-(SP)` — uses the **current** SP (no stack switch).
2. Reads word `$FF0516` (sign-extended) → A1; loads long `[A1 + $20002]` → A0;
   `JSR (A0)` — **RAM-indexed ROM pointer table at $00020002**. This is the
   hybrid dispatch site; the per-mode VBlank routine pointer lives in ROM.
3. Clears word `$FF0516` to 0.
4. `JSR $006D96`, `JSR $098000` (sound/music service candidates).
5. `$004E14: ADDQ.W #1,$FF0288` — **per-VBlank frame counter (word)**.
6. `MOVEM.L (SP)+,D0-D7/A0-A6` ; RTE.

| player_object | TODO | — | not yet identified (needs gameplay-phase RE) |

Runner reads vint_runcount as a **longword**; Boogerman's counter is a word.
At $FF0288 the long read is `(counter<<16) | word($FF028A)`. Current uses in
the runner are change-detection/diagnostics; if audio pacing misbehaves,
revisit (candidate: find a true longword counter, or adapter-side shim).
